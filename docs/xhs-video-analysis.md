- **AI 没法替你点 Cloudflare 后台** —— 它能写代码、能推送、能自动发布，但「把仓库连到 Cloudflare」这一步必须你自己在网页后台点一次（约 2 分钟）。之后就再也不用管了 —— 这是唯一的手动环节，说清楚反而显得靠谱。
- **确认号是真的危险** —— 机票凭确认号 + 姓氏就能改签甚至取消。让 AI 只写航班号和时间，确认号留在你邮箱里。

- **让它主动挑刺，比让它排行程更值钱** —— 这次它发现：7:15 的早班机意味着当天早上没有游览时间、周一闭馆的博物馆只能周六去、租车还车时段柜台关门属于无人值守。这些是行程表本身看不出来的。

- 整个过程**手机能搞定九成**，只有一步建议坐到电脑前 —— 去 Cloudflare 点一次「连接仓库」，五分钟。这一步做完就永久生效了，之后再也不用管。

- 发布后链接形如 `<页面名>.<你的Cloudflare账号名>.workers.dev`，链接**永远不变**，AI 推一次代码就自动上线。

### 4.4 「你需要提供的信息」（INPUT，逐字转写，t ≈ 126–132s）

小标题：越具体越好，但都不是必需 —— 缺什么 AI 会问，或者直接给建议。

- **机票订单截图** —— AI 能直接从截图里读出航班号、起降时间，并据此排整个行程。我这次就是票买早了，它把所有安排往前挪重排了一遍。

## 7. GitHub + Cloudflare 部署步骤（视频中实际执行的版本）

### 7.1 一次性配置

```text
1) 注册 GitHub 账号（3 分钟，免费）
2) 注册 Cloudflare 账号（3 分钟，免费）
3) 在 claude.ai/code 里连接 GitHub
   （或在 设置 → Connectors 里授权），让 AI 能把页面推上去
4) AI 写出页面并 push 到仓库（你只负责描述需求 + 来回聊）
5) Cloudflare Dashboard → Workers & Pages → Create → Workers → Import a repository
      · 选仓库：Josie999777/daily-todo
      · 生产分支：main
      · Build command：留空
      · Deploy command：npx wrangler deploy
   它会读到仓库里的 wrangler.jsonc；首次构建完成后
   texas.josietravelbook.workers.dev 就上线了
6) 给页面起名字（= 网址前缀，只能用小写英文）
7) 之后每次修改：跟 AI 说一句 → AI push 合进 main → 页面几十秒内自动更新
   （实测从合并进 main 到页面更新完成 47 秒，中间没有人操作）
```

### 7.2 关键坑：Worker 名字决定网址前缀

视频 t ≈ 210–225s 专门讲了这个问题（AI 原话，逐字）：

> **为什么必须做这一步：** Cloudflare 的规则是 `workers.dev` 的网址前缀 = **Worker 的名字**。当初在 Dashboard 导入仓库时，名字那栏默认填了仓库名 `daily-todo`，所以网址成了 `daily-todo.josietravelbook.workers.dev`。改名成 `texas` 之后就变成 `texas.josietravelbook.workers.dev`，和你的 chicago 一个规律。这个字段只存在于 Cloudflare 账户里，仓库代码改不了它 —— 我能改的仓库那边（`wrangler.jsonc` 里）早就写的是 `texas` 了。

改名路径（AI 给出的操作指引）：

> 首选方案就是改个名 —— 进 **Workers & Pages → 点开 `daily-todo` → Settings → Rename 成 `texas`**。只有在 Rename 入口找不到的情况下才需要删除重建那条备选路，那是保底，不是主方案。

另外，Git 连接的 Worker 在 Dashboard 里的名字必须和仓库 `wrangler.jsonc` 里的 `name` 一致，否则后续构建会出问题。

### 7.3 为什么不让 AI 直接 `wrangler deploy`

AI 在会话里解释过（t ≈ 203–205s）：

- `wrangler login` 是交互式 OAuth，要弹浏览器回跳 `localhost`，在无头远程环境里天然走不通；
- 无头环境下 `wrangler` 只认 `CLOUDFLARE_API_TOKEN` 环境变量；
- 当时那个仓库「两样都没有：没有 wrangler 配置、没连 Cloudflare、环境里没 token」。

所以走 **Git 连接部署**（最常见、推荐）：在 Cloudflare Dashboard 里把 Worker 连上 GitHub 仓库（Workers Builds），之后 push 即发布。

备选路径（视频里提到但没走）：在 `claude.ai/code` 的环境设置里加 `CLOUDFLARE_API_TOKEN`（权限只需 **Workers Scripts: Edit**），并把网络策略放行 `api.cloudflare.com`，AI 就能在会话里直接 `wrangler deploy`。

## 9. 复刻构建规格（Build Spec）

以下是把视频里这套东西**原样复刻**所需的完整规格，可直接作为实现依据。

### 9.1 交付物

单个静态 HTML 文件 `<行程名>/index.html`，零外部依赖（CSS / JS / SVG 全部内联），部署在 Cloudflare Workers 静态资产模式下，公开可访问。

### 9.2 仓库骨架

```text
<repo>/
├── <trip-slug>/
│   └── index.html          # 本次行程手册，单文件、零外链
├── wrangler.jsonc          # Worker 名 = <trip-slug>，静态资产模式
├── README.md               # 目录结构 + 部署方式
└── （可选）其他行程目录 / 历史页面
```

`wrangler.jsonc` 要点：
- `name` 必须等于 Cloudflare Dashboard 里 Worker 的名字（决定 `https://<name>.<account-subdomain>.workers.dev`）
- 使用 Workers **静态资产（assets）** 模式，把行程目录指为资产目录，`index.html` 自动作为首页伺服
- 提交前用 `npx wrangler deploy --dry-run` 校验，确认它正确识别到了页面文件

### 9.3 数据模型（页面内联的 JS 常量即可）

```text
trip:
  title, emoji, subtitle(日期区间 / 人数 / 进出城市 / 总里程)
  timezone: "America/Chicago"           # 所有时间点统一带时区
  chips: [{icon, label, state: done|pending}]
flights: [{dir: out|back, date, weekday, carrier, no, status,
           from:{iata,city,time}, to:{iata,city,time}, duration, note}]
days:   [{n, date, weekday, title, routeSummary, driveMinutes,
          mapEmbedUrl, navUrl,                  # 当日多点导航链接
          items:[{time, title, note, tags:[需订票|已订|免费], placeUrl}]}]
stays:  [{night, date, name, address, phone, checkIn, checkOut, note}]
todos:  [{group, n, title, status: done|todo, syncedLabel, detail, links:[{text,url}]}]
tips:   [{title, body}]
```

### 9.4 页面结构（从上到下，严格对应作者 prompt）

1. **页头**：标题 + 副标题 + 状态徽章条
2. **「此刻关注 · NOW」卡片**
   - 计算逻辑：在所有 `days[].items` 的绝对时间里找出「下一个未发生的事件」，取其标题 + 备注
   - 大号等宽倒计时 `N天 HH:MM:SS 后`，`setInterval` 每秒刷新
   - 底部「当前待办」行：`todos` 中第一条 `status=todo`，右侧 `去清单 →` 锚点
3. **章节导航 pill**：总览 / 航班 / 每日行程 / 待办清单 / 贴士，点击平滑滚动
4. **行程总览**：一段导语 + 内联手绘感 SVG 地图 + D1–Dn 摘要列表
5. **航班（已出票）**：左右两张卡片（去程 / 回程）
6. **每日行程**：每天一张卡片（日期块 + 标题 + 路线摘要 + 展开地图 + Google 导航 + 时间轴）
7. **待办清单**：分组、编号、只读状态标记
8. **实用贴士**

### 9.5 交互规格

| 功能 | 实现要点 |
| --- | --- |
| 地点点击唤起导航 | 地点文字加虚线下划线，`<a href="https://www.google.com/maps/dir/?api=1&destination=<经纬度或地址>">`，`target="_blank"` |
| 当日全天多点导航 | `https://www.google.com/maps/dir/?api=1&origin=<起>&destination=<终>&waypoints=<途经点用 \| 分隔>&travelmode=driving` |
| 展开当日路线地图 | 卡片内折叠区，展开后插入 Google Maps `<iframe>`（懒加载，展开时才设 `src`）；按钮文案在「🗺 展开今日路线地图 / × 收起地图」间切换 |
| 倒计时 | 所有时间以带时区的 ISO 字符串存储；用 `Intl.DateTimeFormat` + 固定 `timeZone` 计算，避免观看者本地时区算错 |
| 当天自动高亮 | 按当前时间给对应的 day 卡片加高亮样式 |
| 深色模式 | `@media (prefers-color-scheme: dark)` 自动换配色，无需手动开关 |
| 待办勾选 | **明确不要做成可交互 checkbox**；状态写死在页面里，改状态 = 改页面 = 重新部署 |
| 离线可看 | 零外部 CSS/JS/字体；只有地图 iframe 需要网络，其余内容离线可读 |
| 响应式 | 移动端单列、桌面端总览地图与航班卡片并排 |

### 9.6 内容与安全约束

- 页面上**不得出现**：确认号、证件号、房间号、密码
- 航班只写航班号与时间；酒店只写名称、地址、电话、入住/退房时间
- 页面永远保持"终稿"状态，不放修改日志或版本说明
- 行程排布以**已出票的航班时间为锚**，时间对不上就整体重排
- AI 需主动核对：博物馆闭馆日、节假日售罄风险、需要提前预约的免费景点、开车时长是否合理，并主动指出冲突与风险


## 10. 复刻时值得注意的差异点

1. **Worker 名字 ≠ 仓库名**。Dashboard 导入仓库时会用仓库名当默认 Worker 名，必须手动 Rename 成你想要的网址前缀，`wrangler.jsonc` 里的 `name` 改了也盖不过 Dashboard 的字段。
2. **一个仓库可以放多个行程页面**。作者的 `daily-todo` 仓库同时放了 chicago（根目录 `index.html`）和 texas（`texas/index.html`）。若要多个独立子域，需要为每个页面建独立 Worker。
3. **AI 无法替你点 Cloudflare 后台**。除非你在 AI 环境里注入 `CLOUDFLARE_API_TOKEN`（权限仅需 Workers Scripts: Edit）并放行 `api.cloudflare.com`。
4. **待办清单必须是只读的**。这是多人共享场景下唯一正确的做法。
5. **时区是这个页面最容易出错的地方**。作者用的是德州中部时间，观看者在加州，倒计时必须按行程地时区计算。
