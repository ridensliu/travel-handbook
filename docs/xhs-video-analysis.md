## 3. ⭐ 作者给 AI 的完整起手 Prompt（逐字转写）

出现位置：视频 t ≈ 156–165s（以及 t ≈ 285–294s 结尾回看）。作者把它做成了一份网页版说明文档，标题区标注 `TEMPLATE`，卡片头部标注 `PROMPT · COPY & PASTE`，右侧有一个「复制全文」按钮。

文档标题：**给观众的起手 Prompt**

副标题（逐字）：

> 整段复制发给 AI，把【】里换成自己的目的地。这是按这次真实做下来的经验写的，不是通用模板。

### 3.1 Prompt 正文（逐字，可直接复制）

```text
我要去【城市】旅行【X 天】，【几】个人，帮我做一个旅行手册网页。

【部署】
· 单个 HTML 文件，零外部依赖，手机打开快、离线也能看
· 部署成公开网址，任何人点开就能看，不用登录、不用装 App
· 用免费的 Cloudflare Workers，走 GitHub 连接自动发布（我 push 你就上线）
· 需要我亲手操作的步骤一次性列清楚，并告诉我哪几步必须在电脑上做

【页面结构，从上到下】
1. 顶部「此刻关注」卡片：下一个行程事件 + 大号倒计时（天/时/分/秒，每秒跳动）
2. 行程总览地图：手绘感的 SVG，按天用不同颜色画路线，标出每晚住哪
3. 已确认的机票 / 租车 / 酒店 / 门票，写清时间、地址、电话
4. 逐日行程：左边时间、右边内容，需要提前订票的标出来
5. 待办清单：纯列表，不要做成可勾选的（勾选只存在各自浏览器里，多人看到的不一样）。
   办完一项我告诉你，你改页面
6. 实用贴士

【交互】
· 每个地点可点击，直接唤起 Google 地图导航
· 每天顶部能展开当日路线地图，并一键打开全天多点导航
· 白天黑夜自动换配色
· 倒计时和所有时间点都要带时区，跨时区打开不能算错

【内容原则】
· 我会陆续发机票、酒店、门票的截图给你，你自己从截图里提取信息，不用我打字
· 以已经出票的航班时间为锚排行程，时间对不上就整体重排，别硬塞
· 帮我核对：博物馆闭馆日、节假日售罄风险、需要提前预约的免费景点、开车时长是否合理
· 发现我的安排有冲突或风险，直接说，别顺着我
· 确认号、证件号、房间号不要写进页面 —— 公开网址谁都能看
· 页面永远保持终稿状态，不要放修改日志或版本说明

先别动手。等我把订单截图发完，你跟我确认一遍信息，再开始做。
```

> 排版说明：原文档中加粗强调的是这几处 —— 「**并告诉我哪几步必须在电脑上做**」「**纯列表，不要做成可勾选的**」「**你自己从截图里提取信息**」「**以已经出票的航班时间为锚**」「**发现我的安排有冲突或风险，直接说，别顺着我**」「**先别动手。等我把订单截图发完，你跟我确认一遍信息，再开始做。**」

## 4. 使用的 AI 工具与完整工作流

### 4.1 AI 工具

**Claude Code（`claude.ai/code`）** —— 视频 t ≈ 99s 字幕原话：「这一个网页是通过 **Claude Code** 来做的」。文档 `前置准备与分工` 第 03 步同样写明：

> 在 `claude.ai/code` 里连接 GitHub（也可以在 **设置 → Connectors** 里授权），AI 才能把写好的页面推上去。

作者强调整个流程「手机能搞定九成」—— 即用手机跟 Claude 对话即可完成绝大部分工作，只有 Cloudflare 那一次「连接仓库」建议坐到电脑前完成。

### 4.2 「前置准备与分工」（PREP，逐字转写，t ≈ 105–114s）

小标题：**只有前五步需要你动手，一次性，之后所有更新都是 AI 完成。**

右侧标注了每步的执行者（你 / AI）与耗时：

| # | 步骤 | 执行者 · 耗时 | 说明（逐字） |
| --- | --- | --- | --- |
| 01 | 注册 GitHub 账号 | 你 · 3min | 页面代码存在这里，同时是版本历史，随时能退回旧版。免费。 |
| 02 | 注册 Cloudflare 账号 | 你 · 3min | 负责把页面发布到全球，让任何人都能访问。免费。 |
| 03 | 把 GitHub 授权给 AI | 你 · 1min | 在 `claude.ai/code` 里连接 GitHub（也可以在 设置 → Connectors 里授权），AI 才能把写好的页面推上去。 |
| 04 | AI 写出页面并推到仓库 | AI | 你只需要描述想要什么，来回聊几轮改到满意。 |
| 05 | 在 Cloudflare 点一次「连接仓库」 | 你 · 2min | 点开会直接落在 **Workers & Pages** 的 **Create** 页，选 **Import a repository**，选中仓库、分支选 **main**。这一步建立了「代码一更新就自动发布」的通道。 |
| 06 | 给页面起个名字 | 你 · 1min | 这个名字就是网址前缀，比如叫 `texas`，网址就是 `texas.你的名字.workers.dev`。只能用小写英文。 |
| 07 | 之后每次修改 | AI · 47s | 跟 AI 说一句就行，改完自动上线，链接永远不变。 |

### 4.3 关键提醒（视频与文档反复强调）

- 整个过程**手机能搞定九成**，只有一步建议坐到电脑前 —— 去 Cloudflare 点一次「连接仓库」，五分钟。这一步做完就永久生效了，之后再也不用管。
- **全程零元。**
- 发布后链接形如 `<页面名>.<你的Cloudflare账号名>.workers.dev`，链接**永远不变**，AI 推一次代码就自动上线。

### 4.4 「你需要提供的信息」（INPUT，逐字转写，t ≈ 126–132s）

小标题：越具体越好，但都不是必需 —— 缺什么 AI 会问，或者直接给建议。

- **机票订单截图** —— AI 能直接从截图里读出航班号、起降时间，并据此排整个行程。我这次就是票买早了，它把所有安排往前挪重排了一遍。
- **几个人、几号到几号、从哪进哪出** —— 决定租车、住宿和每天的节奏。
- **想去的地方** —— 有清单就发清单，没有就让它推荐 —— 它会考虑闭馆日、节假日售罄、开车距离。
- **订好的酒店和门票** —— 随时补充，AI 填进对应那天，没订的会留在待办清单里提醒你。
- **喜欢的参考页面** —— 有看着顺眼的网页就发给它，可以照着做风格。
- **不要给的：确认号、证件号、密码** —— 页面是公开的，这类信息一律不上页面。

## 7. GitHub + Cloudflare 部署步骤（视频中实际执行的版本）


### 7.2 关键坑：Worker 名字决定网址前缀

视频 t ≈ 210–225s 专门讲了这个问题（AI 原话，逐字）：

> **为什么必须做这一步：** Cloudflare 的规则是 `workers.dev` 的网址前缀 = **Worker 的名字**。当初在 Dashboard 导入仓库时，名字那栏默认填了仓库名 `daily-todo`，所以网址成了 `daily-todo.josietravelbook.workers.dev`。改名成 `texas` 之后就变成 `texas.josietravelbook.workers.dev`，和你的 chicago 一个规律。这个字段只存在于 Cloudflare 账户里，仓库代码改不了它 —— 我能改的仓库那边（`wrangler.jsonc` 里）早就写的是 `texas` 了。

改名路径（AI 给出的操作指引）：

> 首选方案就是改个名 —— 进 **Workers & Pages → 点开 `daily-todo` → Settings → Rename 成 `texas`**。只有在 Rename 入口找不到的情况下才需要删除重建那条备选路，那是保底，不是主方案。

另外，Git 连接的 Worker 在 Dashboard 里的名字必须和仓库 `wrangler.jsonc` 里的 `name` 一致，否则后续构建会出问题。

### 7.3 为什么不让 AI 直接 `wrangler deploy`

AI 在会话里解释过（t ≈ 203–205s）：

- `wrangler login` 是交互式 OAuth，要弹浏览器回跳 `localhost`，在无头远程环境里天然走不通；
- 无头环境下 `wrangler` 只认 `CLOUDFLARE_API_TOKEN` 环境变量；
- 当时那个仓库「两样都没有：没有 wrangler 配置、没连 Cloudflare、环境里没 token」。

所以走 **Git 连接部署**（最常见、推荐）：在 Cloudflare Dashboard 里把 Worker 连上 GitHub 仓库（Workers Builds），之后 push 即发布。

备选路径（视频里提到但没走）：在 `claude.ai/code` 的环境设置里加 `CLOUDFLARE_API_TOKEN`（权限只需 **Workers Scripts: Edit**），并把网络策略放行 `api.cloudflare.com`，AI 就能在会话里直接 `wrangler deploy`。
